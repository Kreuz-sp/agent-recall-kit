# 已知限制（0.1.0 预览版）

这份清单是**发布内容的一部分**：不粉饰、不把"没验"说成"没问题"。

## 1. 领域规则放在 profile 里，不是"通用召回"

对象、目标字段、提示词、字段加权、证据规则全部来自 profile（见 `docs/PROFILE.md`）。
默认 `STARTER` 只有空的**对象/目标表**：这时检索退化为"词面 + 图可达"，不会按对象加权。

- 演示 profile（`examples/config/profile-demo.json`）只对演示库成立，**不是**通用规则；
- 换到你的库必须重写 profile，否则某些问法会被判成 `no_match` 或 `insufficient`；
- 我们没有做"自动从库里学规则"，也不打算在本版本里做。

## 2. 关联候选的生成很保守，且有上限

- 触发条件：同一对象下、两个条目标题有共同词（去除噪声词），**不判断是否同一事件**；
- 每批最多 200 条候选（`candidate.max_candidates`），每个对象最多 60 个条目（`max_units_per_object`）；
- 界面与文档都按"当前生成的候选"表述，**不是**全部潜在关系；
- 需要人逐条看两端原文再决定；接受/拒绝都会持久化，但没有批量接受。

## 3. 来源只读

- `source-readonly` 模式不写你的资料目录（扫描/取原文都是只读）；
- 人工决定、停用状态、布局都写进 `state_root`/`view_root`；
- 想让程序改原件，本版本没有这个能力，也不在路线图承诺里。

## 4. 图更新要手动

- 改了资料后必须 `build`（或界面上的"重新读取来源"）才会进图；
- 没有文件监视、没有自动增量索引；单库全量重建在作者自用库（约 2800 节点）约 1–3 秒量级，仅供规模参考。

## 5. 宿主供给差异

- 本包只提供 **MCP stdio 桥**（`agent-recall-kit-mcp`），把"查询/取原文"暴露给宿主；
- "每轮对话自动把记忆塞进提示词"属于**各宿主自己的适配**，不在本包内，默认不启用、也不替你改宿主配置；
- 不同宿主对 MCP 的支持程度不同；我们只在 `adapters/mcp/README.md` 里给出通用配置片段，未逐家验证。

## 6. 检索的已知缺陷（来自作者自用语料，尚未修）

- **把"怎么样"当方法类问题**：`hints.procedure` 会匹配"怎么"，于是"X 怎么样"会被当成"怎么做"，通常返回 `insufficient`（缺步骤）而不是直接回答评价。
- **评测回显污染**：如果记忆库里某段文字直接抄了评测问句或检索描述，它会被词面命中并进入结果；目前只做了降权（`hints.echo`），没有排除。
- 这两条属于检索质量问题，本版本**只记录不修**。

## 7. 并发与多进程写：未验证

- 同一端口只允许一个服务（操作系统 bind 失败兜底），**但这只说明端口独占**；
- **没有验证**同一数据目录被多个进程同时写（单写者靠文件锁 + 快照发布，但未做多进程压力测试）；
- 不要拿"端口已独占"推断"存储支持多进程写"。

## 8. 平台与界面

- 实测：**Windows 11 + Python 3.12.10 / 3.13.15**（各自全新 venv 装 wheel 跑通）；
  `requires-python = ">=3.12"`，**3.10 / 3.11 未验证**，不承诺可用。
- Linux/macOS 未验证。
- 浏览器实测用 Microsoft Edge（headless）；其他浏览器未逐一验证。
- 界面是管理界面，不做移动端适配。
- 全图在约 2800 节点时首次可交互约 0.6–0.7 秒（作者机器，Edge headless）；更大的库会更慢。

## 9. 其他

- 没有账号体系；连接码是单机共享令牌，任何拿到它的人都能读写这张图（但仍只在本机监听）。
- 没有多用户/权限分组；`access_scope: private` 只是元数据，不做访问控制。
- 没有自动升级/迁移脚本；快照格式变化时请先备份。
- `experience`（经验草稿沉淀）工具未纳入本版本：它与作者侧的工作流和目录约定耦合太深，
  抽成通用工具需要重写一遍，留到下一版（不承诺时间）。
